# Plus11 FastAPI + Next.js integration plan

## User-approved scope and choices

The user selected the existing Python/FastAPI service in `https://github.com/Anas300113/Plus` as Plus11's authoritative learning backend and asked to deploy it alongside the current frontend. The user later selected `https://github.com/Anas300113/PlusDash` as the dashboard delivery repository; it is public and currently has no branches or existing history. Keep the Next.js 16 App Router/TypeScript/Framer Motion frontend and PDF-derived design. Use the already approved managed MySQL database and Manus OAuth account flow. Do not force-push, delete data, seed unapproved questions, or expose FastAPI as a second public service. The initial push creates `main` in the empty PlusDash repository; keep the Manus-managed project as the deployment/checkpoint source and do not switch its canonical repository.

## Architecture and implementation

Run both processes inside the existing Webdev server container. FastAPI/uvicorn binds only to loopback port 8001; Next.js is the sole public listener and honors the platform `PORT`. The Next API routes remain the browser-facing same-origin BFF. They validate the existing `webdev_app_session`, then forward its short server-side Bearer token to private FastAPI endpoints. FastAPI validates HS256 using `MANUS_JWT_SECRET`, checks `exp` and `appId === MANUS_PROJECT_ID`, derives a stable pseudonymous internal `student_id` from the signed `openId`, and never trusts a path, body, or `X-Student-Id` as identity. Add a small authenticated `/api/me` surface for learner name/profile, available approved-question catalog, dashboard, progress, review, and owned session actions; preserve existing learning logic as the state-machine source of truth. Real-data mode stays fail-closed for old ID-only routes. There is no parent role or email/password system in this scope.

Adapt the supplied SQLAlchemy engine and additive migration runner for managed MySQL/PyMySQL with certificate-verifying TLS while retaining the repository's SQLite test behavior. Use the managed `DATABASE_URL` only at runtime. Schema creation remains an explicit, idempotent command (`python -m src.core.migrate`); it is never triggered by import. The production supervisor may invoke that command only when `PLUS_RUN_MIGRATIONS=1`, after both HTTP listeners have bound, so readiness can answer while preparation runs. Keep the existing `plus11_*` tables untouched; the FastAPI/SQLAlchemy learning models are the source of truth going forward. No test writes or deletion against the shared user database; use isolated SQLite fixtures for write-path tests and read-only health checks.

Use only the backend's existing approved question catalog for signed-in practice. The current frontend's sample questions remain a clearly labelled guest demo and are checked server-side; correct answers/explanations remain server-only until a response is checked. If the managed database contains no approved questions, show a clear learner-facing empty state rather than marking demo or unreviewed material as real progress. Practice, streak/mastery, review scheduling, and recommendations must use the Python learner engine and its records; do not maintain a second Next-owned learner datastore.

Use `scripts/supervise.py` for both local development and production: start private FastAPI, bind Next as the sole public listener, then run the gated additive migration while both listeners can answer. Shut both services down on failure. The DB-backed internal readiness route must return success only after Next can reach FastAPI and FastAPI can reach the required schema. Use a multi-stage container compatible with pinned Node and Python 3.12. Keep credentials/runtime DSNs out of build-time and browser output. Preserve public route-manifest rules.

## Design direction

This is an **Operate** extension of the existing Plus11 interface, not a redesign. Preserve Ink `#141414`, warm Paper `#FBFAF6`, Page `#FFFFFF`, Pencil `#5A5A55`, and Highlighter `#FFD84D` reserved for progress/selection/wins. Continue Patrick Hand headings, Nunito for close-reading/question/body text, at least 12px type, crisp rounded 1.5–2px outlines, modest corners, the owl-on-open-book mark, and generous whitespace. Keep the account action in the header and retain the four Today/Learn/Progress/Review learner destinations. Preserve keyboard use, visible focus, 44px targets, contrast, responsive 375/768/1024/1440px layouts, reduced motion, stable loading, and non-punitive truthful content. Do not add gradients, glass, a new palette, decorative grids, unreviewed content, or unnecessary personal fields.

## Project structure

- `src/app` contains Next page routes, the account screen, same-origin auth/BFF routes, `/health`, and the public static route manifest.
- `src/components` contains the existing Plus11 learner interface, with guest/demo and account-backed states; signed-in actions call only Next BFF paths.
- `src/lib/auth.ts` remains the Manus OAuth/session/cookie/CSRF boundary; `src/lib/learner-service.ts` becomes a server-only HTTP adapter to FastAPI rather than a MySQL learner store; public question metadata and server-only guest answer keys remain separate.
- `src/api`, `src/core`, and `src/learning` host the supplied FastAPI, SQLAlchemy models/engine, explicit migrations, verified identity dependency, and existing learning-state machine. Add only `/api/me/*` identity-derived routes while keeping legacy routes fail-closed in real-data mode.
- `tests/` retains and extends the original FastAPI SQLite-isolated suite for MySQL dialect SQL, signed identity, ownership, approved-only content, and question feedback; it must not write synthetic rows to the shared MySQL database.
- `scripts/supervise.py` manages local and production dual-process startup, optional explicit migrations, readiness, and graceful shutdown; `Dockerfile` builds Next and the Python API into one image with Next as the only public listener.
- The Plus FastAPI source/docs/tests are retained in the integrated project. The PlusDash repository has no prior `main` history, so a normal initial push creates its `main`; the Manus project is checkpointed independently and remains the deployment source.

## Dependencies and operations

Keep the existing pinned pnpm policy, Next.js 16, React, Framer Motion, and `jose`. Add pinned/locked Python 3.12 dependencies for the existing FastAPI/uvicorn/SQLAlchemy runtime, `PyMySQL`, `PyJWT`, and existing knowledge-index requirements. The Python MySQL driver must verify TLS using the managed DSN's `ssl` requirement. Keep `MANUS_*` credentials and `DATABASE_URL` runtime-only. Run the additive FastAPI schema migration only through the approved runtime flow against the shared project database, verify migration/readiness with reads only, start both services, validate account/guest boundaries and screens, checkpoint to the Manus-managed repository, push PlusDash `main` without enabling auto-publish, and publish only as already requested after the combined deployment is validated.
